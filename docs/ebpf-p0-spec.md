# P0 — Observer Skeleton Spec

**Parent:** `docs/ebpf-redesign.md` (phase P0). **Baseline:** `docs/ebpf-audit.md`.
**Locked decisions in force:** D1 Docker-only (interface-ready), D2 host-observer-now, D3 CO-RE for
Tier A, D8 Go/cilium-ebpf binary + NDJSON subprocess boundary.
**Status:** spec only — implement against this; no code in this pass.

## 1. Goal & non-goals

**P0 proves the pipeline end-to-end with one minimal program:** load a CO-RE object from a static Go
binary, attach a cgroup-filtered tracepoint, stream events as NDJSON to a Python collector, and
**demonstrate cgroup isolation** — the target container's events arrive, a control container's do not.

**In scope:**
- Go observer binary (`bpf2go` CO-RE build) with one tracepoint program.
- In-kernel cgroup-id filtering via a BPF map populated from userspace.
- `BPF_MAP_TYPE_RINGBUF` → NDJSON emitter (stdout or unix socket).
- Python `DockerTargetResolver` (container ref → cgroup id + init pid) behind a `TargetResolver` protocol.
- Python `ObserverClient` (spawn binary, await `ready`, stream events, stop).
- An acceptance test asserting isolation between two containers.

**Explicitly NOT in P0** (later phases):
- openat/file-load parsing & Package-Index (P1/P2) — P0's program is exec-only, used purely as the
  vehicle to prove the pipe. It is the seed of P3, not throwaway.
- Any verdict/correlation wiring into `correlate_coverage` (P5).
- Dispatch integration into `_run_compose_mode` — P0 is exercised **only** by its own test harness;
  the agent is not modified. (Wiring point noted in §8.)
- containerd/CRI resolver, DaemonSet (P9). Tier B enrichment (P8).

## 3. The CO-RE program — `bpf/observer.bpf.c`

Minimal, one tracepoint. Pseudocode (final code fills CO-RE reads):

```c
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_core_read.h>

char LICENSE[] SEC("license") = "GPL";           // GPL required: bpf_get_current_cgroup_id etc.

struct event {
    __u64 cgroup_id;
    __u32 pid;
    __u32 ppid;
    char  comm[16];
    char  filename[128];
};
struct event *_unused __attribute__((unused));    // force BTF emission of struct event for bpf2go

struct {                                           // target cgroup ids; userspace fills this
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 64);
    __type(key, __u64);
    __type(value, __u8);
} targets SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 1 << 24);                  // 16 MiB
} events SEC(".maps");

SEC("tracepoint/sched/sched_process_exec")
int handle_exec(struct trace_event_raw_sched_process_exec *ctx) {
    __u64 cg = bpf_get_current_cgroup_id();
    if (!bpf_map_lookup_elem(&targets, &cg))       // ── cgroup filter (the P0 assertion) ──
        return 0;

    struct event *e = bpf_ringbuf_reserve(&events, sizeof(*e), 0);
    if (!e) return 0;

    e->cgroup_id = cg;
    e->pid = bpf_get_current_pid_tgid() >> 32;
    struct task_struct *t = (struct task_struct *)bpf_get_current_task();
    e->ppid = BPF_CORE_READ(t, real_parent, tgid);
    bpf_get_current_comm(&e->comm, sizeof(e->comm));
    // filename: read via ctx __data_loc (best-effort; may be empty in P0)
    bpf_ringbuf_submit(e, 0);
    return 0;
}
```

Notes:
- **cgroup filtering is the entire point of P0.** `bpf_get_current_cgroup_id()` returns the cgroup v2
  id (= inode of the cgroup dir). Only ids present in `targets` pass.
- `sched_process_exec` chosen because it is low-volume, deterministically triggerable
  (`docker exec … /bin/true`), and its struct becomes the basis of P3.
- GPL license string is mandatory for the helpers used.

## 4. Go binary — CLI contract & lifecycle

```
vulnreach-observer
  --cgroup-id <u64>        target cgroup id; repeatable for multiple containers / a pod
  --output <path|- >       NDJSON sink: "-" = stdout (default), or a unix socket path
  --duration <secs>        optional auto-stop (0 = run until SIGTERM)
```

Lifecycle:
1. Parse flags; require ≥1 `--cgroup-id`.
2. `RemoveMemlock()`, load embedded CO-RE objects (cilium/ebpf `loadObserverObjects`).
3. Populate `targets` map from `--cgroup-id` values.
4. Attach `handle_exec` (`link.Tracepoint`).
5. Emit **one** control line `{"type":"ready", ...}` (§5) — this replaces the old
   1.5 s-sleep-and-poll attach check; the Python side blocks on it.
6. `ringbuf.Reader` loop → marshal each event to an NDJSON `event` line.
7. On SIGTERM/SIGINT or `--duration` expiry: stop reader, emit `{"type":"summary",...}`, exit 0.
8. Any fatal error before `ready`: emit `{"type":"error",...}` to stdout **and** non-zero exit.

Exit codes: `0` clean; `1` load/attach failure; `2` bad args. Errors always surface as an `error`
NDJSON line first so the Python side gets a structured reason (no stderr scraping).

## 5. On-wire schema (NDJSON — one JSON object per line)

Control lines:
```json
{"v":1,"type":"ready","cgroup_ids":[4026531841],"kernel":"6.1.0","prog":"sched_process_exec"}
{"v":1,"type":"error","msg":"attach failed: permission denied"}
{"v":1,"type":"summary","events":42,"dropped":0,"duration_ms":30000}
```
Event lines (P0):
```json
{"v":1,"type":"exec","ts_ns":123456789,"cgroup_id":4026531841,"pid":8123,"ppid":8100,"comm":"true","filename":"/bin/true"}
```

Contract rules:
- `v` is the schema version (bump on breaking change; the Python reader asserts `v==1`).
- `ts_ns` is a monotonic boot-time nanosecond stamp (not wall clock).
- Unknown `type` values must be ignored by readers (forward-compat).
- The stream is the **record/replay seam**: fixtures for P2/P5/P7 are captured NDJSON files.

## 6. Python — `TargetResolver` & `ObserverClient`

```python
# agents/ebpf/target_resolver.py
from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True)
class ResolvedTarget:
    container_id: str
    cgroup_id: int        # cgroup v2 inode; matches bpf_get_current_cgroup_id()
    cgroup_path: str      # e.g. /sys/fs/cgroup/system.slice/docker-<id>.scope
    init_pid: int         # host-ns PID (for /proc/<pid>/root in P2+; unused in P0)
    runtime: str = "docker"

class TargetResolver(Protocol):
    def resolve(self, container_ref: str) -> ResolvedTarget: ...

class DockerTargetResolver:
    """v1 resolver (D1). Uses `docker inspect` + /proc + /sys/fs/cgroup."""
    def resolve(self, container_ref: str) -> ResolvedTarget:
        # 1. docker inspect -> .Id, .State.Pid  (reuse _get_container_pid pattern)
        # 2. read /proc/<pid>/cgroup ; cgroup v2 line is "0::<path>"
        # 3. cgroup_id = os.stat("/sys/fs/cgroup" + path).st_ino
        ...
```

`cgroup_id` derivation (the crux — must match the kernel's value):
1. `docker inspect --format '{{.Id}} {{.State.Pid}}'` → id, init_pid.
2. Read `/proc/<init_pid>/cgroup`; the cgroup v2 entry is the line prefixed `0::`.
3. `st_ino` of `/sys/fs/cgroup<path>` **is** the cgroup id returned by `bpf_get_current_cgroup_id()`.
   ⚑ Assumption A1: **cgroup v2 unified hierarchy.** cgroup v1 has different id semantics — detect
   and fail fast with a clear message (v1 support is out of P0 scope).

```python
# agents/ebpf/observer_client.py
class ObserverClient:
    def __init__(self, binary_path: str): ...
    async def start(self, cgroup_ids: list[int], duration: int = 0): ...
        # asyncio.create_subprocess_exec(binary, --cgroup-id ..., --output -)
        # read stdout lines; parse NDJSON; block until {"type":"ready"} or raise on {"type":"error"}/timeout
    async def events(self):  # async iterator yielding parsed event dicts
        ...
    async def stop(self):    # SIGTERM, drain, await summary, return counts
        ...
```

Mirrors the existing async-subprocess patterns (`_start_ebpf_tracer`/`_collect_ebpf_hits`) but reads
structured NDJSON instead of scraping bpftrace stdout, and uses the `ready` line instead of a sleep.

## 7. Acceptance test — `tests/test_ebpf_observer_p0.py`

Gated: `@pytest.mark.skipif` unless Linux + root (CAP_BPF/CAP_PERFMON) + docker + cgroup v2 + kernel
≥5.8. Matches the existing `tests/test_ebpf_e2e.py` skip conventions.

**Isolation test (the P0 pass/fail):**
1. `docker run -d` two throwaway containers: **T** (target) and **C** (control), e.g. `sleep 300`.
2. `resolver.resolve(T)` → `cgid_T`; `resolve(C)` → `cgid_C`; assert `cgid_T != cgid_C`.
3. `ObserverClient.start([cgid_T])`; await `ready`.
4. Trigger execs in both: `docker exec T /bin/true` and `docker exec C /bin/true`.
5. Collect events for a short window, then `stop()`.
6. **Assert:** ≥1 event with `cgroup_id == cgid_T` and `comm in {"true"}`;
   **zero** events with `cgroup_id == cgid_C`; zero events from host execs run during the window.
7. Teardown: `docker rm -f T C`.

**Contract tests (no docker, run in normal CI):**
- Feed a recorded NDJSON fixture through the `ObserverClient` parser → assert typed events, `ready`
  handling, `error`-line raises, `v!=1` rejected.
- `DockerTargetResolver` cgroup-path parsing unit-tested against sample `/proc/<pid>/cgroup` text.

## 8. Build, deps, and future wiring

- **Build deps (build-time only):** Go ≥1.22, `clang`/`llvm` (bpf2go invokes clang), `bpftool` (for
  `make vmlinux`). **Runtime deps: none** beyond the kernel — the object is embedded, CO-RE handles
  per-kernel relocation via BTF at `/sys/kernel/btf/vmlinux`.
- **Makefile:** `make vmlinux` (dump BTF→`vmlinux.h`), `make generate` (bpf2go), `make build`
  (static `bin/vulnreach-observer`), `make test`.
- **Privilege (P0):** `CAP_BPF` + `CAP_PERFMON` to load+attach; ringbuf needs no extra cap.
  `CAP_SYS_PTRACE` / `/proc/<pid>/root` access is **not** needed until P2. Full `privileged` avoided.
- **Config (future, not P0):** add an `ebpf.engine: "legacy" | "observer"` switch to `EbpfSettings`
  (`config/schema.py`) so the agent can dispatch to the observer path. P0 leaves the agent untouched;
  the eventual call site is `_run_compose_mode`'s eBPF dispatch (`agent_dynamic_reachability.py:1479`).

## 9. Kernel requirements & assumptions

| Requirement | Reason |
|-------------|--------|
| Kernel ≥ 5.8 | `BPF_MAP_TYPE_RINGBUF`, `CAP_BPF`/`CAP_PERFMON` |
| BTF at `/sys/kernel/btf/vmlinux` | CO-RE relocation without kernel headers |
| cgroup v2 unified hierarchy (A1) | `bpf_get_current_cgroup_id()` == cgroup dir inode; the whole filter depends on it |
| Not LinuxKit/Docker Desktop | syscall tracepoints unavailable (same gate as audit `_ebpf_available`) |

## 10. Definition of done (P0)

1. `make build` produces a static `vulnreach-observer` on a stock Linux CI image.
2. Running it with a target cgroup id streams well-formed NDJSON `ready` + `exec` lines.
3. `tests/test_ebpf_observer_p0.py` isolation test passes: target execs captured, control execs absent.
4. Contract tests pass in header-less CI (no docker/root).
5. No changes to `agent_dynamic_reachability.py` or existing eBPF paths — P0 is additive and isolated.

⚑ Only open question that could change P0 code: **A1 cgroup v2 assumption** — confirm all target
environments are cgroup v2 (modern Docker/K8s are). If cgroup v1 must be supported in v1, that adds a
resolver branch and changes the id derivation. Everything else is settled by D1–D3/D8.
